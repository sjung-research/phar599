최신 코드 받기 (git pull) 설명서

GFAP 농도 곡선 분석 프로그램 (gfap-conc) · 노트북과 연구실 컴퓨터 공용 · 2026-11-27

1. 이 설명서로 하는 일

Claude가 코드를 고치면 GitHub 저장소(sjung-research/phar599)에 올라갑니다. git pull은 그 최신 코드를 내 컴퓨터의 프로젝트 폴더로 가져오는 명령입니다.

  • 프로젝트 폴더 (두 컴퓨터 모두): C:\Users\sjung3\Documents\phar599
  • 사용하는 창: Windows PowerShell. Anaconda Prompt는 쓰지 마세요.
  • 원칙: 명령은 한 번에 한 줄씩 붙여넣고 Enter를 누릅니다. 두 줄을 한꺼번에 붙여넣으면 오류가 납니다.
왜 폴더 이동(cd)이 먼저 필요한가요?
PowerShell을 새로 열면 항상 C:\Users\sjung3(홈 폴더)에서 시작합니다. git과 uv 명령은 지금 있는 폴더에 대해 동작하므로, 먼저 프로젝트 폴더로 들어가야 합니다. PowerShell을 껐다 켰다면 매번 2단계부터 다시 합니다.

2. 단계별 진행

1단계PowerShell 열기

시작 메뉴를 열고 PowerShell을 입력한 뒤 Windows PowerShell을 클릭합니다. 창이 열리면 맨 아래 줄이 이렇게 보입니다.

PS C:\Users\sjung3>

2단계프로젝트 폴더로 이동 (PowerShell을 열 때마다 필수)

cd $HOME\Documents\phar599

성공하면 줄 앞부분이 프로젝트 폴더로 바뀝니다.

PS C:\Users\sjung3\Documents\phar599>

$HOME은 C:\Users\sjung3를 뜻합니다. 같은 명령이 노트북과 연구실 컴퓨터 모두에서 동작합니다.

3단계(권장) 현재 상태 확인

git status

정상이라면 다음과 비슷하게 나옵니다.

On branch claude/blissful-cori-wjn019
Your branch is up to date with 'origin/claude/blissful-cori-wjn019'.
nothing to commit, working tree clean

results\ 폴더와 config\analysis.yaml은 git이 일부러 무시하므로 여기에 나오지 않는 것이 정상입니다. 분석 결과와 설정은 git pull로 지워지지 않습니다.

4단계최신 코드 받기

git pull

둘 중 하나가 나오면 정상입니다.

Already up to date.

→ 이미 최신 상태입니다. 바뀐 것이 없습니다.

Updating b330699..e97bb25
Fast-forward
 src/gfap_conc/plots.py | 120 +++++++++
 ...

→ 새 코드를 받았습니다. 바뀐 파일 목록이 표시됩니다.

처음이거나 로그인이 만료되었으면 브라우저 창이 열리며 GitHub 로그인을 요청합니다. 비공개 저장소라서 정상입니다.

5단계필요한 패키지 맞추기

uv sync

새 코드가 다른 패키지 버전을 필요로 할 수 있어서, git pull 뒤에는 항상 실행합니다. 바뀐 것이 없으면 금방 끝납니다.

6단계(권장) 테스트로 확인

uv run pytest

마지막 줄에 92 passed처럼 모두 통과(passed)가 나오면 준비가 끝났습니다. 테스트 수는 코드가 바뀌면 달라질 수 있습니다. failed가 있으면 그 출력을 Claude에게 그대로 보내세요.

3. 그다음: 분석 다시 실행하기 (참고)

새 그림 기능을 받은 경우 분석을 다시 실행해야 결과 폴더에 새 그림이 생깁니다. 같은 PowerShell 창에서 이어서 입력합니다.

uv run gfap-conc run --config config\analysis.yaml

결과 폴더 열기:

explorer (Get-ChildItem results\real -Directory -Filter "run_*" | Sort-Object LastWriteTime | Select-Object -Last 1).FullName
이미 review를 확정했으므로 다시 review할 필요가 없습니다. 같은 .lif 파일과 같은 설정을 쓰는 한 확정은 유효합니다. 실행할 때마다 results\real\run_날짜-시간 폴더가 새로 생기고, 예전 결과는 지워지지 않습니다.

4. 문제가 생겼을 때

화면에 나온 메시지원인과 해결
fatal: not a git repository프로젝트 폴더 밖에 있습니다. 2단계(cd $HOME\Documents\phar599)를 먼저 하세요. 현재 위치는 Get-Location으로 확인할 수 있습니다.
Cannot find path ... phar599
(cd 할 때)		이 컴퓨터에 아직 프로젝트를 받지 않았습니다. 처음 한 번만 아래를 실행합니다.
cd $HOME\Documents
git clone -b claude/blissful-cori-wjn019 https://github.com/sjung-research/phar599.git
'git' 또는 'uv' 용어가 ... 인식되지 않습니다프로그램이 설치되지 않았거나, 설치 직후 창을 다시 열지 않았습니다. PowerShell을 닫았다 다시 열어 보고, 그래도 안 되면 docs\RUNNING_ON_WINDOWS.md의 설치 단계를 따르세요.
Your local changes to the following files would be overwritten by merge추적되는 파일을 직접 수정한 적이 있어서 git이 덮어쓰기를 멈춘 것입니다. 지우지 말고 그 출력을 Claude에게 보내세요. 수정한 내용이 필요 없다면 git stash 후 다시 git pull을 하면 됩니다.
브라우저 로그인 창이 열림정상입니다. GitHub 계정으로 로그인하면 git pull이 계속 진행됩니다.
명령이 이상하게 붙어서 실행됨
(예: ...yamlCopy-Item ...)		두 명령을 한 번에 붙여넣었습니다. 한 줄씩 다시 실행하세요.
uv run pytest에서 failed출력 전체를 Claude에게 보내세요. 분석은 테스트가 모두 통과한 뒤에 실행하는 것이 안전합니다.
공용 컴퓨터에서: 다른 사람도 같은 Windows 계정을 쓴다면 작업 후 GitHub 로그인을 지우세요. Windows 자격 증명 관리자 → Windows 자격 증명에서 git:https://github.com을 제거하면 됩니다. 다음 git pull 때 다시 로그인을 묻습니다.

5. 한 장 요약

PowerShell을 새로 열 때마다, 아래 순서대로 한 줄씩:

cd $HOME\Documents\phar599
git pull
uv sync
uv run pytest

분석을 다시 돌릴 때만 이어서: uv run gfap-conc run --config config\analysis.yaml
